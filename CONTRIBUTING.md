# Contributing

:+1::tada: First off, thanks for taking the time to contribute! :tada::+1:

It's people like you who make todo.txt such a great tool.

The following is a set of guidelines for contributing to todo.txt and its packages. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

Following these guidelines helps to communicate that you respect the time of the developers managing and developing this open source project. In return, they should reciprocate that respect in addressing your issue, assessing changes, and helping you finalize your pull requests.

todo.txt is an open source project and we love to receive contributions from our community — you! There are many ways to contribute, from writing tutorials or blog posts, improving the documentation, submitting bug reports and feature requests or writing code which can be incorporated into todo.txt itself.

Please, don't use the issue tracker for support questions. Check whether our [Gitter.im] channel can help with your issue, or add a [discussion under Q&A](https://github.com/todotxt/todo.txt/discussions/categories/q-a).

# Ground Rules

## Responsibilities

- Be welcoming to newcomers and encourage diverse new contributors from all backgrounds. See our [Code of Conduct].
- Create issues for any major changes and enhancements that you wish to make. Discuss things transparently and get community feedback.
- Don't add any new features to the rules unless they are core functionality. Most extensions and additions are better implemented as optional, generic extensions to the rules. Only essential stuff used by everyone should be added to the main rules.
- Keep pull requests as small as possible, preferably one new feature per pull request.

# Translations

The todo.txt format specification is translated into multiple languages. Translation files follow the naming convention `README.{language-code}.md` (e.g., `README.ko.md`).

Each translation file includes a status banner at the top indicating when it was last updated. When contributing a translation update, please update the commit ID in the HTML comment inside the status banner.

To help translate todo.txt into your language, see the [status banner](./README.ko.md) in an existing translation for contribution guidance.

# Code review process

The core team looks at Pull Requests on a regular basis. After feedback has been given we expect responses within two weeks. After two weeks we may close the pull request if it isn't showing any activity.
